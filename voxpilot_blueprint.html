[ §00 · ABSTRACT ]

摘要

VoxPilot 的目标是做一个能听、能看、能动手、也能记住的桌面副驾。本规格书不是概念稿，而是经过多轮代码级复审后的施工图纸。

VoxPilot 采用前后端分离的微服务架构：轻量客户端负责 UI、音频采集播放与状态机，本地推理引擎负责模型推理、工具执行与记忆检索。C++ 承担低延迟音频底座，Python 负责逻辑调度与生态整合。

经过六轮评审，文档中所有会导致真机崩溃的实现缺陷已全部修复，包括 pybind11 的 GIL 释放位置、SPSC 队列的并发语义、工具确认机制的竞态与内存泄漏、慢任务进程隔离的 pickle 约束，以及状态机的断头路。V5.2 可作为唯一权威文档冻结，进入 Milestone 1 编码。

[ §01 · VISION ]

愿景与哲学

始于语音，不止于语音。

VoxPilot 想做的是一个环境副驾（Ambient Copilot）——它不只在你喊它的时候响应，也理解你所在的屏幕、正在播放的会议、以及你此刻的状态。它需要“手、脑、眼、耳、魂”五个维度的能力，才能称得上副驾。

核心哲学

Python 负责逻辑调度与生态整合，C++ 负责底层性能。先单体跑通闭环，后微服务拆分；在线极速响应，离线降级可用。这条原则决定了后面所有的技术选型与工程边界。

[ §02 · ROADMAP ]

落地路线图

不要在第一天就去死磕微服务或 AEC。按以下里程碑推进，确保项目存活并平滑迭代。

  1. 环境搭建 Python 3.11 + venv，建立 core/、modules/、cpp_src/、ui/ 空目录。
  2. 极简终端闭环 录音 5 秒 → faster-whisper 识别 → 云端 API 回答 → edge-tts 播放。验证硬件与模型链路。
  3. UI 与异步调度 PyQt6 搭建界面，录音与网络请求放入 QThread，通过信号槽通信，确保界面不卡顿。
  4. 底层重构与打断 C++ SPSC 无锁环形缓冲，webrtcvad 断句，实现 Barge-in 打断。 动手前必须先补并发 pytest
  5. 手和脑 接入 Function Calling（带线程安全的异步确认），封装 Alist 直链下载，让副驾能真正干活。
  6. 微服务化与多模态 接入视觉感知，ASR / LLM / TTS 独立成 FastAPI 服务，客户端仅保留音频硬件交互。

关键实现

SPSC 环形缓冲 · GIL 只包裹搬运循环

cpp_src/audio_ringbuf/ring_buffer.cpp C++ · PYBind11 
// 实际可用容量 = max_capacity - 1，防止 head == tail 空满冲突
size_t do_push(const int16_t* p, size_t n) {
    size_t h = head.load(std::memory_order_relaxed);
    size_t t = tail.load(std::memory_order_acquire);
    size_t free_cnt = (max_capacity - 1) - ((h + max_capacity - t) % max_capacity);
    size_t w = std::min(n, free_cnt);
    for (size_t i = 0; i < w; ++i) buffer[(h + i) % max_capacity] = p[i];
    head.store((h + w) % max_capacity, std::memory_order_release);
    if (n > w) dropped.fetch_add(n - w, std::memory_order_relaxed);
    return w;
}

// GIL 只包裹数据搬运，进出都在 GIL 下
size_t push(py::array_t<int16_t> data) {
    auto buf = data.request();
    int16_t* ptr = static_cast<int16_t*>(buf.ptr);
    size_t written = 0;
    {
        py::gil_scoped_release nogil;
        written = do_push(ptr, buf.size);
    }
    return written;
}
CONTRACT 返回值 < len(data) 表示丢弃，调用方必须记录并告警。head / tail / dropped 均 alignas(64) 防伪共享。

工具确认 · 零竞态与迟到点击感知

core/tools_manager.py · PendingConfirmation Python 
def resolve(self, cid: str, approved: bool) -> bool:
    """返回 False 表示该确认已超时失效，UI 需提示"""
    with self._lock:
        if cid not in self._events:
            return False          # 迟到点击
        self._results[cid] = approved
        ev = self._events.pop(cid)
    ev.set()
    return True

def wait(self, cid: str, timeout: float) -> bool:
    with self._lock:
        ev = self._events.get(cid)
    if ev is None:
        return False
    ok = ev.wait(timeout)
    with self._lock:
        self._events.pop(cid, None)
        result = self._results.pop(cid, False)   # 无论如何都清理
    return ok and result
ZERO-RACE resolve 检查 cid 是否存活（防迟到写入）；wait 超时也无条件清理 _results（防泄漏）；返回值用 ok and result 保证超时语义。

慢任务隔离 · 规避 pickle 崩溃

core/tools_manager.py · SLOW TASK ISOLATION Python 
# 模块级注册表：慢工具必须是模块顶层函数
SLOW_TOOL_REGISTRY: dict[str, Callable] = {}

def download_worker(task_queue, result_queue):
    """独立进程：只处理 (job_id, name, kwargs)"""
    while True:
        task = task_queue.get()
        if task is None:
            break
        job_id, name, kwargs = task
        try:
            res = SLOW_TOOL_REGISTRY[name](**kwargs)
            result_queue.put_nowait((job_id, "success", res))
        except Exception as e:
            result_queue.put_nowait((job_id, "error", str(e)))

# execute 内：job_id 贯穿提交 / 回传 / 查询
job_id = uuid.uuid4().hex
self._download_queue.put_nowait((job_id, name, kwargs))
with self._jobs_lock:
    self._jobs[job_id] = {"status": "queued", "result": None}
return json.dumps({"status": "queued", "job_id": job_id})
ANTI-CRASH 子进程只接收 (job_id, name, kwargs)，通过 name 查表；严禁把 self._tools 传进子进程。队列深度 16，满载拒绝。

[ §07 · CONSTITUTION ]

工程宪法

绝对不可违背的原则。任何代码评审都必须以此为准绳。

  1. GIL 精准释放C++ 接口中的 py::gil_scoped_release 必须精确包裹数据拷贝循环。
  2. 契约明确push 返回 < len(data) 表示丢弃需告警；pop 返回 < size 表示缓冲不足需零填充。
  3. TTS 单消费者严禁多线程并发读 stdout；LLM 必须累积到句号才推入 TTS 有界队列。
  4. AMBIENT 唤醒词语义唤醒词是唯一对话入口。AMBIENT 态喊唤醒词进 LISTENING；退出内录走快捷键或语音命令。
  5. 音频三分与补传麦克风采集永不暂停；ASR 上传 TTS 时暂停；Barge-in 时补传最近 300ms 并恢复上传。
  6. 异常必归 ERROR初始化失败或致命崩溃必须归入 ERROR 态。重启成功才切回 IDLE。
  7. 工具确认零竞态resolve() 必须返回是否生效的 bool。confirm_ui 抛异常时必须清理 cid。
  8. 慢任务绝对隔离慢工具必须是模块顶层函数，写入 SLOW_TOOL_REGISTRY；严禁把 self._tools 传进子进程。
  9. job_id 贯穿慢任务以 (job_id, name, kwargs) 提交，worker 回传 (job_id, status, result)，对外提供 check_job_status。
  10. 双向白名单本地模式下，get_schemas 过滤和 execute 校验必须双重生效。
  11. UI 线程安全confirm_ui 注入时必须通过 pyqtSignal 派发到主线程。
  12. 进程启动约束ToolRegistry 不得在模块顶层实例化。入口脚本必须有 if __name__ == "__main__": 保护。
